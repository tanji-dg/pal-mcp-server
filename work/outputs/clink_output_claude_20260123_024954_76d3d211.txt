=== FINAL CONTENT ===
Hardwire JITのコードを分析した結果、`emit_AdvancePCStop` の実装に重大な欠陥が見つかりました。これが `JBITQ` の Not Taken（分岐しない）ケースや、`OTIR`/`INDR` 等の完了時に、CPUの状態（PCとフラグ）をメモリ上のコンテキストと同期させずにディスパッチャへ戻してしまう原因となっています。

### 原因の特定

1.  **`emit_AdvancePCStop` の実装不備 (`src/hardwire/LC701AJit.cpp`)**
    現在の `emit_AdvancePCStop` は、`rpc` (PCレジスタ) を加算してディスパッチャループの先頭 (`dispatcherLoopLabel_`) へジャンプするだけの実装になっています。
    ```cpp
    void LC701AJit::emit_AdvancePCStop(int len) {
        this->add(rpc, len);
        this->advancePC(len);
        this->stopBlock_ = true;
        jmp(*dispatcherLoopLabel_, JMP_TYPE); // <--- ここで問題発生
    }
    ```
    ディスパッチャループの先頭では、`rflags` をメモリ (`ctx->flag64` または `cpuCtx->flag_`) から**再ロード**します。`emit_AdvancePCStop` が直前の命令（`JBITQ`など）で更新されたフラグをメモリに書き戻していないため、**フラグが命令実行前の古い状態に巻き戻ってしまいます**。
    また、`PC` もメモリに書き戻されていないため、コンテキストスイッチやデバッグ時に不整合が生じます。

2.  **`JBITQ` での発生機序**
    `2100.yaml` の `JBITQ` 命令において、条件が成立せず分岐しない（Not Taken）パスを通る場合、`emit_AdvancePCStop(4)` が呼ばれます。
    ```cpp
    // OPEA_HandleJBITQ in LC701AJit_OPEA.cpp
    // Not taken
    emit_AddCycles(5);
    emit_AdvancePCStop(4); // <--- ここを通るとフラグとPCが保存されない
    ```
    これにより、`JBITQ` で更新されたはずのフラグ（Z/TZなど）が失われ、後続の命令実行で不正な状態（ループ脱出条件の誤判定など）を引き起こし、最終的にクラッシュにつながっている可能性があります。

### 修正案

以下の2つの修正を適用してください。

#### 1. `src/hardwire/LC701AJit.cpp` の修正

`emit_AdvancePCStop` を `advancePCStop` と同様に、状態をメモリに同期するように修正します。

```cpp
#if LC701A_HARDWIRE_DIRECT_CPUCTX
            mov(word[rCpu + offsetof(LC701ACpuContextLayout, regPC_)], rpc);
            mov(qword[rCpu + offsetof(LC701ACpuContextLayout, flag_) + offsetof(LC701ACpuContextLayout::Flag, ull_)], rflags);
#else
            mov(word[rContext + offsetof(LC701AContext, PC)], rpc);
            mov(qword[rContext + offsetof(LC701AContext, flag64)], rflags);
#endif
            jmp(*dispatcherLoopLabel_, JMP_TYPE);
        }
    }
}
```

#### 2. `src/hardwire/LC701AJit_OPEA.cpp` の修正（推奨）

`OPEA_HandleJBITQ` 内の到達不能コードを削除し、ロジックを整理します。

```cpp
// src/hardwire/LC701AJit_OPEA.cpp

bool LC701AJit::OPEA_HandleJBITQ(uint8_t sub) {
    // ... (前半はそのまま) ...
    // Update flags
    ror(rflags, 32); mov(getLowReg8(rflags), 1); rol(rflags, 32);    // H
    ror(rflags, 8);  mov(getLowReg8(rflags), 0); rol(rflags, 8);     // N
    ror(rflags, 16); mov(getLowReg8(rflags), 0); rol(rflags, 16);    // PV
    ror(rflags, 48); mov(getLowReg8(rflags), rScratch8); rol(rflags, 48); // Z
    ror(rflags, 40); mov(getLowReg8(rflags), rScratch8); rol(rflags, 40); // TZ
    ror(rflags, 56); mov(getLowReg8(rflags), 0); rol(rflags, 56);    // S

    Label L_Taken, L_End; // L_End は不要になりますが、ラベル定義だけなら残しても無害
    if (condZ) {
        test(rScratch8, rScratch8);
        jnz(L_Taken, JMP_TYPE);
    } else {
        test(rScratch8, rScratch8);
        jz(L_Taken, JMP_TYPE);
    }

    // Not taken
    emit_AddCycles(5);
    emit_AdvancePCStop(4); 
    // jmp(L_End, JMP_TYPE); <--- 削除（emit_AdvancePCStopは戻ってこないため到達不能）

    L(L_Taken);
    // Taken: jump relative to START of instruction + 4
    add(rpc, (int16_t)4 + (int16_t)disp);
    and_(rpc_full, 0xFFFF);
    emit_AddCycles(6);
    this->advancePCStop(4);

    // L(L_End); <--- 削除
    return true;
}
```

この修正により、`emit_AdvancePCStop` を使用するすべての命令（`JBITQ`, `OTIR`, `INDR`, `INIR`, `OTDR` 等）で、フラグとPCが正しく同期されるようになります。
